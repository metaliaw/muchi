# Paired Repositories

> Provisional. Written from practice, not yet Weathered.

- Two repositories that change Together Name each other.  
  Each root `MEMORY.md` Holds a *Paired Repositories* section.
- The Section Records the Path, never the Story.  
  One path, one line of Role, and `owner/name` where the path does not say it.
- The Pair is Symmetric.  
  If A lists B, B lists A, in the same Words.
- Write the Path relative to this repository, never from a Home.  
  A Machine changes, the Layout between the two Checkouts does not.
- When both Checkouts are Present, do not ask again.  
  Read the Section, Check the Path Exists, and Work across the Boundary.
- A Path in Memory is a Claim, not a Fact.  
  Verify it before Editing another repository, and Fix the Section when it Lies.
- The Canon Teaches the Habit, never Keeps the Addresses.  
  A repository that Adopts OneTwoThree Records its own Pairs;
  this one does not list them.

## What the Section Looks Like

```md
## Paired Repositories

These repositories are commonly worked on locally together. Paths are
relative to this repository:

- `.` — `owner/this-repo`, what it Owns (this repository).
- `../../owner/other-repo` — what it Owns.

For changes across their boundary, inspect and update both repositories using
these paths. Do not ask the user for their locations again when both checkouts
are present.
```

## Why a Memory and not a Question

The Boundary between two repositories is where a change Breaks.  
An Agent that does not Know where the other Side lives will Edit one half
and Guess the other.

Asking Costs the person the same Answer, every session.  
A Line in `MEMORY.md` Costs one Edit, once.

This rule is *Provisional*.  
It came from one Pair, and has not yet Survived a second.
